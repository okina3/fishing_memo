# FishingMemo

## アプリ概要

釣果の再現性を高めることを目的とした、釣り記録アプリです。

FishingMemoは、場所・天候・仕掛け・時間などの情報を一元管理し、
釣行日や備考をもとに検索・整理・共有できるようにすることで、
効率的にデータを活用できるようにしたWebアプリです。

釣りをしていて何も釣れないと、原因が分からないまま時間が過ぎてしまい、
貴重な休日が無駄になってしまうという課題がありました。

そこで、釣れた日の条件（場所・天候・仕掛け・時間など）をノートに記録し、
再現性を高めようとしましたが、記録漏れやデータの集計に手間がかかるという問題がありました。

本アプリでは、釣りに関する情報を一元管理し、
検索・整理・共有できるようにすることで、
効率的にデータを活用し、釣果の再現性向上を支援することを目的としています。

また、ユーザーが継続的に記録しやすいよう、
入力のしやすさや操作性にも配慮して設計しました。

## 工夫した点

### ① データの一元管理と再利用性

釣りに必要な情報（場所・仕掛け・エサなど）を、マスターデータとして管理し、入力の効率化と再利用性を向上させました。

また、入力ミスや表記ゆれを防ぐことにも繋げています。

### ② 入力途中の離脱を防ぐためのUX改善

本来、場所・仕掛け・エサなどはマスターデータとして事前に登録する設計にしていましたが、実際の利用を想定すると、新規メモ作成中にマスターデータが未登録であることに気づき、入力内容を一度破棄して登録し直す必要があるという課題がありました。

この問題を解決するため、新規メモ作成画面から直接マスターデータを追加できるようにし、入力途中でも作業を中断せずに完結できるよう改善しました。

また、通常の入力操作の妨げにならないよう、マスターデータの登録はモーダルで行う設計とし、必要なときのみ利用できるUIとしています。

これにより、ユーザーの入力ストレスを軽減し、継続的な利用を促す設計としました。

### ③ 画像管理の最適化

画像アップロード時にリサイズ処理を行い、ストレージ負荷の軽減と表示速度の改善を行いました。

### ④ CI/CDの導入

GitHub Actionsを用いて、テストとデプロイを自動化し、開発効率と品質の向上を図りました。

### ⑤ 運用・不具合を考慮した設計

ブラウザバックによる再送信で同じデータが登録される可能性があるため、セッションを用いた二重送信防止を実装しました。

また、共有画面のURLにユーザーIDがそのまま表示されることで、IDの推測が可能になると考え、encrypt / decrypt を用いて暗号化しました。

さらに、不正利用を想定し、管理者によるユーザーの利用停止・削除機能を実装し、運用面での対応も考慮しています。

## インフラ構成

Dockerでローカル開発環境を構築し、GitHubでコード管理を行っています。

GitHub Actionsにより、テストおよびデプロイを自動化しています。

本番環境はAWS（EC2）上に構築し、Docker上でLaravelアプリケーションを、Apacheサーバーで稼働させています。

<br>
<br>

# GitHub Actions CI/CD

- Githubへのdevelopブランチのマージ時に、テストを実行します。
- テストが成功した場合、EC2へのデプロイが自動で実行されます。
